# 汉化审查当前结论

生成依据：

```powershell
.\scripts\audit-localization.ps1 -Scope all -Output docs\localization-audit-current.md
```

最近一次结果：

| 分类 | 数量 | 处理方式 |
| --- | ---: | --- |
| `must_review` | 50 | 继续人工判定，当前剩余项大多是协议字段、测试输入或外部 payload |
| `mixed_review` | 195 | 检查是否是命令/API/品牌名/路径，避免误改 |
| `could_review` | 3781 | 多数是代码、协议、注释，低优先级 |
| `skip_tech` | 1028 | 默认不汉化 |

## 本轮已处理

TUI 明确可见英文已经处理，覆盖范围包括：

- 启动输入跳过、默认图片提问、命令目录不可用。
- 语音连续模式提示、协议噪声提示、等待输入提示。
- 确认、sudo 密码、密钥输入等状态提示。
- 剪贴板图片、取消提示、忙碌状态、退出码显示。
- skill 相关加载、空消息、命令不明确、技能列表标题。
- 技能中心和 `/skills` 命令的普通说明词。
- 状态栏和 `/details` 帮助里的普通 `Agent` 说明词。
- 后台任务、子代理数量、目标状态、顶部状态栏映射。

飞书显示和边缘错误文案已经处理，覆盖范围包括：

- webhook HTTP 错误文本。
- 飞书消息解析占位：图片、附件、表情、富文本、合并转发、共享聊天、交互消息。
- 文件内容展示前缀、共享聊天详情、聊天 ID。
- 注册/连接 CLI 的主要提示。
- `aiohttp` 缺失时的 webhook 模式提示。
- 飞书评论规则 CLI 的常用输出。

`lark-cli-toolbox` 当前结论：

- 工具描述基本已中文。
- bot 身份链路可用。
- user 身份需要单独登录后才能覆盖个人文档、个人消息、日程等 user-scope 能力。

## 剩余待复核

审查脚本仍会保留一批 `must_review`，但当前不应直接批量汉化：

- 协议字段、配置键、事件名、JSON 字段、API 枚举值。
- `feishu`、`lark`、`post`、`text`、`message_type`、`open_id`、`union_id` 等协议值。
- provider/model 名称、环境变量、文件路径、URL、MIME type。
- 测试里的模拟输入和断言上下文。
- 外部平台原始 payload 透传内容，例如用户原文、文件名、服务端返回摘要。

## 后续审查规则

1. 新增可见文案时，先判断它属于 TUI、飞书、CLI、日志、协议还是测试。
2. TUI、飞书卡片、CLI 面向用户输出默认应中文。
3. 命令名、flag、配置键、协议值、API 字段默认不翻译。
4. 每轮汉化后必须重跑审查脚本和对应测试。
5. 剩余 `must_review` 不能直接视为问题，必须结合调用路径判定是否真实可见。
